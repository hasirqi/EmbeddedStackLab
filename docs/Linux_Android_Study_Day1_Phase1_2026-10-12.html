5. 第一个 Linux C 程序

文件：hello.c

#include <stdio.h>

int main(void)
{
    printf("Hello Linux\n");
    return 0;
}

编译

gcc -g -Wall hello.c -o hello

参数含义：

参数作用
-g加入 Debug 信息，后续可用 GDB 调试。
-Wall打开常用编译警告。
-o hello指定输出可执行文件名为 hello。

运行

./hello

实际结果：

Hello Linux

6. 今天遇到的一个真实问题：复制粘贴异常

从 Mac 向 Ubuntu Terminal 粘贴命令时，曾出现类似：

^[[200~gcc -g -Wall hello.c -o hello~

这会导致 Shell 把控制字符也当成命令的一部分，从而出现：

gcc: command not found
关键判断：GCC 实际并没有坏。通过 which gcc 已确认： 
/usr/bin/gcc

同时确认 PATH 正常：

/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:...

因此真正的问题是 Terminal 粘贴时混入控制字符，不是 GCC 安装失败。

后续如果再次出现 ^[[200~ 或命令结尾多一个 ~，先手工输入命令验证，不要急着重装软件。

7. 第一阶段已经建立的核心认识

   ↓

   ↓

   ↓

   ↓

   ↓

   ↓

8. 下一阶段

接下来不是继续装软件，而是开始真正观察 Linux：

然后再只观察关键 System Call：

strace -e trace=write,exit_group ./hello

        ↓
