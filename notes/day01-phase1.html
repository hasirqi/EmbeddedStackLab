6. 创建第一个 Linux C 程序

创建源码：

nano hello.c

文件内容：

#include <stdio.h>

int main(void)
{
    printf("Hello Linux\n");
    return 0;
}

7. 第一次编译

编译命令：

gcc -g -Wall hello.c -o hello
参数作用
-g加入 Debug 信息，后续可以用 GDB 调试。
-Wall打开常用编译警告。
-o hello指定输出可执行文件名称为 hello。

编译成功后没有错误输出，这是正常的。

8. 第一次运行

执行：

./hello

实际输出：

Hello Linux
这是第一个完整的 Linux 开发闭环：写源码 → GCC 编译 → 生成可执行文件 → Linux 启动进程 → 程序输出结果。

9. 今天遇到的真实问题：复制粘贴异常

从 Mac 向 Ubuntu Terminal 粘贴命令时，出现过类似：

^[[200~gcc -g -Wall hello.c -o hello~

这会让 Shell 把控制字符也当成命令的一部分，从而出现：

gcc: command not found

为了确认 GCC 本身是否正常，实际执行过：

which gcc

返回：

/usr/bin/gcc

进一步检查：

ls -l /usr/bin/gcc

实际返回：

lrwxrwxrwx 1 root root 6 Jan 31  2024 /usr/bin/gcc -> gcc-13

同时检查 PATH：

echo $PATH

实际结果：

/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin:/snap/bin
结论：GCC 没有问题，PATH 也没有问题。真正的问题是复制粘贴时混入了 Terminal 的 bracketed paste 控制字符。
以后如果再次出现 ^[[200~ 或命令结尾多出 ~，先手工输入关键命令验证，不要因为一条错误信息就急着重装软件。

10. GCC 路径确认过程

今天还实际使用了：

which gcc

这个命令用于确认当前 Shell 最终会调用哪个 GCC。

返回：

/usr/bin/gcc

说明：

Shell ↓ PATH 搜索 /usr/bin/gcc ↓ symbolic link gcc-13

11. 第一阶段已经建立的核心认识

今天还没有深入 Kernel Driver，但已经跑通最基本的 Linux 开发闭环：

写 C 代码 ↓ gcc 编译 ↓ 生成 ELF 可执行文件 ↓ Linux 启动程序 ↓ 程序执行 ↓ 终端看到输出

下一阶段要继续把这条链向下拆：

printf() ↓ glibc ↓ system call ↓ write() ↓ Linux Kernel

主要观察工具：

strace

12. 下一阶段准备执行的命令

完整观察程序：

strace ./hello

只看关键 System Call：

strace -e trace=write,exit_group ./hello

目标是实际看到类似：

write(1, "Hello Linux\n", 12) = 12
exit_group(0) = ?

并真正理解：

printf("Hello Linux\n") ↓ glibc ↓ write(...) ↓ System Call ↓ Linux Kernel
