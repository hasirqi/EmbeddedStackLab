知识体系

这里只保存值得长期复用的概念、逻辑、架构、调试方法和工程经验。

Architecture

系统调用链

Android App ↓ Android Service ↓ Binder / AIDL ↓ HAL ↓ open / read / write / ioctl ↓ Linux Kernel ↓ Device Driver ↓ Hardware
Linux

Userspace → Kernel

printf() 并不直接控制硬件。真正重要的是理解 libc、system call、VFS、file descriptor 与 Kernel 边界。

Driver

Kernel Driver

后续沉淀 probe、remove、file_operations、ioctl、Device Tree、I²C/SPI/GPIO 等。

Android

HAL / Binder / AIDL

重点不是背术语，而是理解每一层解决的边界问题、接口约束和跨进程调用链。

Debug

Layer 切分

建立统一方法：先判断问题在哪一层，再选择工具，而不是从头到尾乱查。

gdb     → 进程内部
strace  → Userspace / Kernel 边界
dmesg   → Kernel / Driver
logcat  → Android Framework / Service / HAL
Engineering

大型代码阅读

原则：先找 Interface，再找入口，再沿 Call Path 追踪。不要试图“把几十万行代码全部读完”。
